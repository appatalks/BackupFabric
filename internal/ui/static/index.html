Backup inventory

Register an appliance

Register each source, its dedicated GHES receiver, and each restore target separately. Configure native remote archives on GHES using GitHub's documentation.

Configure SSH and topology

Register the receiver's SSH profile first, then map its source. Each receiver may belong to only one source. Keys and independently verified host keys must be mounted by the server administrator; never paste private keys here.

Login is fixed to admin. Host, role, and receiver mapping cannot be rebound after registration. No sudo wrapper or GHES configuration modifications are performed.

Native backup / receiver collection

Run a backup on the source, then separately collect its receiver after native remote synchronization completes. BackupFabric cannot currently prove remote-sync completion.

Restore staging wizard

This transfers the complete retained history to an empty target backup root. It does not execute ghe-restore or overwrite an existing history.

Do not initialize/format the target disk. After staging, follow GitHub's native restore procedure and record a full restore rehearsal. Transfer checks are not recoverability checks.

Transfer settings

Live operations run one at a time. No automatic retries, pruning, deletion, host-key enrollment, or native restore execution. Changed settings apply to future operations.

Live operation history

Persisted operation states and approval records. Interrupted operations require inspection before retrying; partial transfers are never usable collections.

Experimental GHES integration. Collected or staged does not mean restore-qualified. Only local trusted administrators may use this unauthenticated interface.
